# Backend: Halves

## Auth

- Email + password, bcrypt cost 12. Session: 32 random bytes in an http-only, SameSite=Lax
  cookie (Secure in production); only the sha256 of the token is stored.
- Invited people are placeholder users (no password). Signing up with that email claims
  the account and its history.
- Account deletion: blocked while any balance is open, then anonymises the user and
  removes sessions, friendships and memberships.
- Password reset: `/forgot-password` emails a one-time link (`/reset-password?token=...`), valid 30 minutes.
  Only the sha256 of the token is stored (`password_resets`). Using it sets the new password, kills every other
  open link for that account and signs out every device. Same reply whether or not the email has an account;
  the email is sent after the response so timing doesn't tell either. Limits: 3 emails per address and
  10 requests per IP per hour. Email goes through Resend (`RESEND_API_KEY`) or any SMTP mailbox (`SMTP_*`).
- Invites: adding a friend, creating a group or adding a member with an email that has no account emails
  that person a sign-up link with their email filled in. One invite per address per 24 hours
  (`users.invited_at`), with a "Resend invite" button on the friend page.
- Every sent email is logged as `[mail] sent "<subject>" to <address>`. `npm run mail:test you@x.com` checks the settings.
- Not built yet: Google sign-in, rate limits on log in and sign up (see checklist).

## Database

- Migrations: `drizzle/` (generated by `npm run db:generate`, applied by `npm run db:migrate`).
- Access rules: data-layer checks in `src/lib/access.ts`; every page and action calls them.
  Tested: a non-member gets a 404 on a group URL (e2e).
- Seed: `npm run db:seed` (fake people, `password123`). `npm run db:reset` wipes and reseeds.

## Jobs

- `GET /api/cron/recurring`, daily via `vercel.json`, `Authorization: Bearer $CRON_SECRET`.

## Payments, email

- None yet. A Pro tier would use Stripe Checkout + Customer Portal; invites and
  reminders would use Resend from your own domain.

## Security checklist

- [x] secrets only in env vars, `.env*` in `.gitignore`, nothing in client bundles
- [x] input validated on the server (zod) on every action
- [x] authorisation checked on every read and write, tested with a second user
- [ ] rate limits on log in and sign up (add before launch: Upstash Ratelimit or the host's WAF)
- [x] webhooks verify signatures (n/a yet; cron uses a constant-time secret check)
- [x] no uploads yet
- [x] no user data in URLs (ids only) or logs
- [x] CSV export neutralises spreadsheet formula injection
- [ ] dependencies audited (`npm audit`) before deploy
- [ ] privacy policy lists every processor (host, database, email)
